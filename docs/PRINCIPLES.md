# Principles

Founding decisions, written down so future-us doesn't drift.

## 1. Mirror, not grade

The Dayplayer is for **self-recognition**, not self-optimization. No focus
scores, no streaks, no leaderboards, no "productivity rating." The moment it
smells like surveillance or optimization porn, the magic ("this is literally
me") dies and we're a fitness tracker with reverb.

## 2. Never the employer edition

No manager dashboards, no team comparisons by default, no B2B surveillance
version. One "boss listens to employees' days" news story kills the trust
brand forever. (Opt-in duets between friends are different — both sides
press play.)

## 3. Revise the mapping, never the concept

If renders sound like mush, the **mapping** (features → music) gets revised.
The concept — timings only, day → piece, blind test as gate — stays.

## 4. The blind test is the gate

Continue if the real-timing render is distinguishable and you *want to hear
it again*. Revise the mapping if it's mush. Stop claiming success if only
the technical render works but hearing it tells you nothing.

## 5. The inversion is the product

"The instrument plays you until you learn to play it." Every feature must
deepen that loop, not fight for attention against it.

## 6. Local-first forever

Raw data on the user's disk. Sharing = sharing rendered audio, explicitly.
See TRUST.md.

## Roadmap shape

- **Stage 1 (now):** Python proof — recorder, composer, synth, blind test.
  Gate: distinguishability, tested by a human (you).
- **Stage 2:** Tauri shell for double-click install (Mac .dmg + Windows
  .msi), signed/notarized, auto-update; web share-player for renders.
- **Stage 3:** mapping packs, week/month renders ("the audible diary"),
  named patterns (Flow, Flail, Drift, Mire) as the shared vocabulary.
